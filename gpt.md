# BriefGuard — completion contract

## Goal

Continue the existing project into a usable, verifiable local video-review
workflow: user media and explicit requirements → selected frames → an exported
model request → explicitly authorized execution or imported response → evidence
with timestamps.
Preserve the original CPU experiment as a separate reproducible research result.
Full research completion also requires real authorized VLM observations and human
evaluation on documented source media. A new UI or passing tests alone cannot
satisfy that empirical goal.

## Ownership and responsibilities

- Architect: define boundaries, data contracts and acceptance conditions.
- Programmer: implement the user workflow and concise product documentation.
- API engineer: prepare exact requests, validate responses and preserve provenance.
- Tester: verify happy paths, corrupted inputs, limits and regression behavior.
- Critic: challenge usefulness, misleading claims and missing evidence.
- Reviewer: inspect the integrated change independently of implementation.
- Coordinator: resolve findings, verify consistency, commit/publish and report.

## Working rules

Continue on research/briefguard; preserve other work. No default-branch push,
merge, force push or rewritten history. Read current status before making claims.
Keep frozen code, protocol, configuration and original results unchanged. New
experiments and product workflows live separately. Preserve existing pilot locks.

Keep product text and routine documentation about behavior, evidence and usage.
Do not add repetitive authorship narration, autogenerated-work disclaimers or
self-congratulatory process logs. Do not add authorship disclaimers to the UI or
routine documentation. Preserve technical evidence and historical artifacts; do
not invent personal contributions or completed human checks.

No paid request without explicit provider, model and total-budget authorization.
Never expose keys. Exported requests contain no credentials and do not execute.
Live execution is a separate command with a fixed model and persistent budget
shared by workbench runs in this checkout; no approval is assumed here.
Never fill human labels, impersonate reviewers or present fixture responses as
real inference. Imported responses are operator-supplied, not authenticated
provider records. A pass concerns selected frames, never all unseen video.

## Deliverables

1. Local workbench for writing requirements and preparing supported media.
2. Offline CLI exporting exact selected images, source timing, immutable manifest,
   unsent request and a readable report.
3. Strict response import with evidence validation and request/response identity.
   A separate opt-in API command reuses the bounded adapter and budget ledger.
4. Meaningful automated tests and preserved host acceptance evidence.
5. Concise instructions, current limitations and a final owner-facing report.
6. Separately recorded empirical pilot after budget, source and human-label gates
   are met. Until then, report empirical completion as blocked rather than done.

## Acceptance

- Original study and all existing pilot locked files remain unchanged.
- A complete offline preparation/import path runs without credentials or network.
- Corrupted bundles and evidence citing unseen frames are rejected.
- Media formats, timing and inspected-frame coverage are stated accurately.
- Actual host installation/Docker evidence is distinguished from browser QA.
- No live model, human-review or natural-video accuracy result is invented.
- Critic/reviewer findings are fixed or explicitly documented.
- Changes are committed; publish if the available environment permits it.

## External gates

Live VLM evaluation still requires model/budget approval and API access outside
chat. Human evaluation requires actual owner annotations. Browser interaction
must be executed in an allowed environment; static checks are not a substitute.
A larger natural-video study requires independently sourced, licensed clips and
its own protocol; do not treat siblings of one video as independent observations.
